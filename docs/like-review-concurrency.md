# 좋아요 및 리뷰 동시 요청 (#84)

- 좋아요 등록/취소와 리뷰 작성은 사용자 행 쓰기 잠금을 먼저 얻는다. 잠금, 중복 확인, 저장/삭제는 하나의 서비스 트랜잭션에서 수행한다.
- 기존 방문 상태 변경과 같은 사용자 잠금 순서를 사용한다. 같은 사용자의 서로 다른 장소 요청도 짧게 직렬화되는 대신 새로운 잠금 테이블/스키마는 추가하지 않는다.
- 동일 장소의 동시 좋아요 등록은 모두 200이며 `(user_id, spot_id)`는 한 건만 저장된다. 동시 취소 역시 200이며 최종 저장 건수는 0이다.
- 등록과 취소가 섞이면 잠금 획득 순서대로 처리된다. 네트워크 응답 도착 순서가 DB 처리 순서라는 보장은 없다.
- 동일 완료 방문의 리뷰 동시 작성은 한 건만 200, 나머지는 기존 `ReviewNotAllowedException` 형식의 409이다.
- DB 유니크 제약은 유지한다. 모든 무결성 오류를 중복 요청으로 취급하거나 500을 무조건 성공으로 바꾸지 않는다.
- 없는 장소, 타인 방문, 미완료 방문의 검증은 유지한다. 존재하지 않는 사용자에 대해서는 401이다.

## 테스트

`LikeReviewConcurrencyIntegrationTest`는 실제 서비스/DB 트랜잭션과 컨트롤러/전역 예외 처리기를 사용한다. 테스트 사용자 인증 정보는 테스트 스레드에만 설정한다. JWT/보안 필터 자체의 테스트는 아니다.

동시에 요청을 시작하고 HTTP 상태, 리뷰 오류 코드, 최종 저장 건수를 검증한다. 각 테스트는 별도 사용자를 생성하며 리뷰/좋아요/방문/장소/사용자 순으로 정리한다.

CI의 별도 MySQL 8.4에서 실행한다. `TEST_REQUIRE_MYSQL=true`일 때 MySQL 연결 여부를 검사해 H2 대체 실행을 허용하지 않는다. 로컬 H2 검증과 실제 MySQL 검증 결과는 구분한다. 운영 DB로 테스트하지 않는다.
