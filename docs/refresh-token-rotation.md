# 리프레시 토큰 회전 (#83)

- 신규 access/refresh JWT에 UUID 기반 `jti`를 추가한다. 같은 초에 발급해도 토큰이 달라진다.
- 기존 JWT의 서명/만료/type 검증은 유지한다. `jti`가 없는 기존 토큰도 유효하고 DB 저장값과 일치하면 재발급할 수 있다.
- 재발급은 사용자 행의 쓰기 잠금을 얻은 뒤 만료와 저장된 토큰을 다시 확인하고 같은 트랜잭션에서 교체한다.
- 같은 refreshToken을 동시에 제출하면 하나만 성공하고 나머지는 기존 InvalidRefreshTokenException(401)을 반환한다. 실패한 재사용 요청이 새 토큰을 지우지는 않는다.
- 로그인과 로그아웃도 동일 사용자 행 잠금을 사용한다. 가입 직후에는 새 사용자 행의 트랜잭션 안에서 토큰을 발급한다.
- 재발급이 먼저 처리되면 뒤따르는 로그아웃이 새 refreshToken을 지운다. 로그아웃이 먼저 처리되면 뒤따르는 재발급은 실패한다. 명시적인 새 로그인은 별도 인증이므로 로그아웃 후에도 새 세션을 발급할 수 있다.
- 로그아웃은 기존대로 refreshToken만 무효화한다. 이미 발급한 accessToken의 즉시 폐기는 이번 범위에 포함하지 않는다.
- 요청/응답 형식과 DB 스키마 변경은 없다. 프론트는 재발급 요청을 합치고 성공 응답의 accessToken/refreshToken을 함께 저장해야 한다.

## 검증

- JwtProviderTest: 같은 시각 발급 토큰의 고유 ID와 토큰 타입 검증.
- AuthRotationIntegrationTest: 재사용 거부, accessToken 오용 거부, 동시 재발급 한 건 성공, 두 가지 로그아웃/재발급 순서 검증.
- 통합 테스트는 DB에 테스트 사용자를 생성/삭제한다. 운영 DB로 실행하지 않는다. CI의 별도 MySQL 서비스에서 실행하며 로컬 H2 검증은 MySQL 검증을 대신하지 않는다.
